## 一个荒诞到让人笑不出来的细节

2026年10月，丹麦。

一家叫Pays ApS的IT服务公司，负责对接丹麦国家人口登记数据库（CPR）。这个数据库里存着丹麦几乎所有公民的个人信息——姓名、地址、身份证号、社保信息。

攻击者拿到了至少三个账户的权限，包括一个管理员账户。

这三个账户的密码是什么？

**123456。**

不是段子。是真实发生的安全事件。880万条公民记录被非法获取。

880万，差不多是丹麦全国人口的1.5倍。

## 你以为这只是丹麦人的问题

我猜你现在的反应是："丹麦人怎么也这么不靠谱。"

但你上次检查自己的密码是什么时候？

你有多少个账户在用生日、手机号后四位、或者"qwerty"？你有多少个平台在用同一个密码？你的Wi-Fi密码是不是印在路由器背面从来没改过？你的NAS管理密码是不是"admin"？

别不好意思。这不是你个人的问题。这是**人类认知能力的结构性缺陷**。

人的大脑不擅长生成随机字符串。人倾向于使用有意义的、好记的组合。人在被要求设置"至少8位含大小写字母和特殊字符"的密码时，会在"Password123!"这种模式上微调——而黑客的字典攻击库早就把这些模式穷举完了。

2026年了。密码管理器在推广，多因素认证在普及，但人类最本能的反应还是——**设一个好记的密码**。

而"好记"和"安全"，在密码学世界里几乎是反义词。

## 密码的问题不在于"不够复杂"，而在于"它根本不该是最后一道门"

让我们把思路往前推一步。

传统的加密模型是这样的：

**数据 + 密码 → 加密 → 密文**
**密文 + 密码 → 解密 → 数据**

在这个模型里，**密码是唯一的、也是最终的防线。** 密码泄露了，一切就没了。密码太弱了（比如123456），一切就形同虚设。

问题在于：这个模型把安全的重担完全压在了人类最不擅长的事上——记住一个足够复杂的随机字符串，并且永远不泄露它。

Pays ApS的管理员设了"123456"。不是他不知道安全很重要。是人脑在"设密码"这件事上天然不靠谱。

**所以，真正的解决方案不是"让人设更好的密码"，而是让整个安全体系不再依赖人能不能记住密码。**

## 全链路无明文：从生到死，你的数据没有一秒钟是"裸"的

DoraBox的另一个关键设计是**全链路加密**。

"全链路"的意思是：你的数据在DoraBox的生命周期里，没有一刻是以明文形态暴露在不安全环境中的。

具体来说：

**生成时：** 你在DoraBox里创建一条笔记、上传一张照片、存储一份文件——操作在你的设备上完成，数据在生成的瞬间就被加密。

**传输时：** 从你的设备到DoraBox服务器，全程TLS加密传输。即使中间有人抓包，拿到的也是密文上再套一层密文。

**存储时：** 服务器上只有密文。没有密钥，没有明文索引，没有任何可以反推原始内容的信息。

**展示时：** 只有在你授权的设备上打开DoraBox时，数据才在本地解密展示。一旦锁屏或退出，明文立刻从内存中清除。

**同步时：** 设备间同步的是密文。接收端用自己的本地密钥解密。中间没有任何"明文经过服务器"的窗口。

用一句话说：**你的数据从出生到消亡，没有在任何一个环节"裸奔"过。**

## 和其他"加密"的区别，一句话就能说清

很多产品说自己"加密"。但它们加密的方式是这样的：

数据 → 用平台的密钥加密 → 存在服务器上 → 需要时用平台的密钥解密

**密钥在平台手里。** 平台能加密，也能解密。平台被攻击了，攻击者拿到密钥也能解密。平台被要求交出数据了，它有能力交出来。

DoraBox的方式是：

数据 → 用你的加密算法进行加密 → 用DoraBox的加密算法离线加密 → 密文存在服务器上 → 需要时用DoraBox的算法解密 → 用你自己的加密算法进行解密

**密钥只在你手里。** DoraBox的服务器上从来没有密钥。DoraBox的团队从来没有、也永远不会有能力解密你的数据。不是因为"承诺不解密"，是因为**技术上做不到**。

前者叫"平台托管加密"——你的安全取决于你信不信这个平台。

后者叫"零知识加密"——你的安全取决于数学定律。

**信任人，人会变。信任数学，数学不会。**
